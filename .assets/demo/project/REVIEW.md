# REVIEW: InsureCast demo (opus)

Delivered: `../demo-insurecast-opus.mp4` (62.5 s, 1920x1080, 30 fps, H.264 High yuv420p, AAC 48 kHz stereo, 10.6 MB), `../poster.png` (t = 2.9 s).

## Creative calls
- Storyline A, "Next year's number" (see `../STORYLINES.md`); B ("the number first") and C ("three questions") not built.
- One continuous take inside the real app; the only transition between chapters is a full-frame #fafafa sheet that whips in from the right and out to the left (5 uses), everything else is camera (1.333x to 2.2x, power2.inOut).
- No caption strip. Words on screen: 4 headline lines (<= 6 words, 112 px Geist 600) and 5 callouts (30 px on screen) anchored to the exact point they describe, each visible 1.6-1.8 s.
- UI = DOM rebuild of the captured page: Tailwind CSS from the running app, Recharts paths from the live render, values from the live API (backend :8010, frontend :3010, separate copies, both stopped). Native selects are drawn as the app's own popover style because a headless capture cannot show the OS menu.
- AI conclusion: an OpenAI key was available, so the real `/ai/forecast-summary` output was captured (no fallback text anywhere). Of three real runs for TX · Construction · LostTime, the one whose numbers match the data was used (61 claims/month, $1,331,177/month average paid; a different run said "$13,311,773.50 over the next year", which is wrong by 10x, and was not used).
- After the scenario update the conclusion keeps that text and adds the app's real scenario notice line; the backend summary endpoint does not take scenario inputs, so the real app would regenerate an equivalent baseline paragraph.
- Font: the app declares Geist; the current dev build falls back to Times because `@theme inline` does not emit `--font-sans`. The film uses Geist (the intended identity). Worth a one-line fix in `globals.css`.

## Measured

- Contrast: 21 errors / 30 warnings, all on the product's own chart axis labels (#a1a1aa on white, the real Recharts styling). Kept on purpose for fidelity; they are secondary labels, the read happens through callouts and headlines.
- Craft warnings kept: `line_unread` on UI text that the camera crops or that changes state by design (old NY conclusion, loading badge, slot-machine "2%/5%"); `text_below_floor` on product UI text (real UI at 1.33-2.2x).
- Audio (rendered file): -15.8 LUFS integrated, LRA 1.4 LU, true peak -1.6 dBTP, no clipping, music from 0.1 s, silence 61.77-62.5 s. Measured, not heard.
- Music: generated with Google Lyria RealTime (4 candidates). All candidates carried narrow-band artefacts above 12 kHz (a 13.6 kHz tone in one), so the chosen bed (light acoustic, ~100 BPM) is low-passed at 12 kHz with a -4 dB low shelf at 110 Hz and a limiter. Clicks: bundled Pixabay `click-soft`; whooshes: two alternating takes, 10-14 dB under the bed.

- No error text, "N/A", "fallback", "OPENAI_API_KEY", localhost, browser chrome or dev overlay in any frame. Spinners only during the two 2.5-2.8 s loading windows (the app's real loading badge).

## Fixed during review
- Unlayered `* { margin:0; padding:0 }` in index.html silently beat Tailwind's layered utilities (whole UI lost padding) -> removed.
- `fromTo` immediate render leaked later states (all y-axis tick sets visible at once) -> `immediateRender:false` everywhere in the app timeline, initial states via `gsap.set`.
- Tailwind `transition-*` rules ran on the browser clock -> stripped at build.
- Slider track 11/29 px off from the live app (native range box + margin collapse) -> measured the rebuilt DOM against the live page; all cursor targets now come from `assets/data/geom-recreation.json`.
- Tooltip text wrapped -> right-anchored, no fixed width. Hook chart too small -> stretched viewBox, 28 px labels.
- Music tail was still -20 dB at 61.8 s -> fade moved to 58.9-61.8 s, 0.7 s of silence at the end.

## Weakest shot / with more time
- 36.4-38.8 s sheet "What if costs rise 10%?": the slot roll is quick (2%/5% read for 0.2 s each by design).
- The table chapter (49.7-53 s) is dense at 1.6x; a tighter crop on the Dec 2026 row would read better on a phone.
- With more time: re-run the LLM until its wording also matches the scenario state, and add a subtle motion-blur pass on the sheet whips.

## v2 (owner fixes: zoom softness, label shake) -> `../demo-insurecast-opus-v2.mp4` (v1 kept)

**Root cause (both issues):** the camera layer `#ic-cam` (and `#ic-scroll`) had `will-change: transform`, and GSAP's default
`force3D: "auto"` used `translate3d` mid-tween. Both promote the zoomed app to a compositor layer that Chrome rasterizes once at
1x and then scales up 1.33-2.2x, so text and SVG looked soft. Which raster scale a promoted layer gets depended on the render
worker's state, so the "12-month SARIMAX forecast" callout alternated between a soft and a crisp raster on every other frame:
the visible shake. Leftover `filter: blur(0px)` after blur-in tweens also kept elements on their own surfaces.

**Changes (nothing else touched):** removed `will-change` from the camera and scroll layers; `gsap.config({ force3D: false })` in
the app scene so every transform stays 2D and the DOM/SVG is painted at its final zoom; blur-in tweens now end with
`filter: none`. Everything inside the zoomed layer is live DOM/SVG (no bitmaps), so it repaints at full resolution at any zoom.

**Verified:**
- Sharpness (Laplacian variance of full 1920x1080 frames at each zoom peak, v1 -> v2): 8.6 s (2.2x) 121 -> 495; 12.8 s 142 -> 576;
  20.5 s (1.72x) 198 -> 573; 27.0 s (1.68x) 287-341 -> 770; 32.5 s 144 -> 418; 40.6 s (2.2x) 78 -> 345; 44.4 s 91 -> 380;
  48.6 s 612 -> 798; 51.8 s (1.6x) 348-482 -> 549-572. Side-by-side crops at 40.6 s confirm crisp glyph edges.
- Shake: 30 consecutive frames from 26.9 s, label region mean abs diff v1 alternated 0.00 / 6.73 every frame; v2 is 0.00 after
  the fade-in. 10-frame holds checked for every other label (callouts a, c, d, e, tooltip, headline sheets, end card): all 0.00.
- Audio and timing unchanged: 62.5 s, -15.8 LUFS, true peak -1.6 dBTP.

**Label blink, root cause.** `callout()` made the wrapper visible at `g` (`tl.set(el, {opacity:1})`) while its parts were
`fromTo` tweens with `immediateRender:false` starting later (dot `g`, leader line `g+0.08`, box `g+0.18`). Until each tween
started, its "from" state was not applied, so the box and line rendered at full opacity for 3-5 frames, dropped to 0 when
their tweens began, then faded in: a visible blink on every pinned note (a-e). Fix: the dot, line and box are set to their
hidden "from" states at `g`, before the wrapper is shown (same-time sets render in insertion order), so each label fades in
once.
